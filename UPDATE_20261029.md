# Update 2026-10-29 — Crushing Validation

## Changes in this package
- Added Master Part fields `SKU (Child)` and `Qty (Child)` with compatibility migration for the existing SQLite database.
- Master Part table now displays SKU and child quantity; the existing search also searches SKU because it filters visible row text.
- Master Part import reads the optional `SKU (Child)` and `Qty (Child)` columns. If the Photo column is blank or absent, existing photo paths are not cleared. New rows are created without a photo unless a photo path is already assigned separately.
- Production part data includes SKU and BOM child quantity. `Pilih Semua` applies `Qty (Child) × Qty FG`; changing Qty FG recalculates selections marked as BOM-derived. The backend checks BOM-derived quantities before saving. Individual part selections remain manually entered. This iteration does not yet add a separate FG-vs-Satuan selector; FG quantity is currently applied through `Qty FG` + `Pilih Semua`.
- Monitoring Top 10 Part chart now uses readable horizontal category labels and Rupiah ticks.
- Leader edit page supports staged part removal and manually adding parts from Master Part, committed when `Simpan & Selesai` is submitted. New manual items are marked `leader_manual` and written to activity log. Tickets already included in a MARIS closing period are locked from edits. The browser warns before leaving with unsaved edits; a server-side save error may still return a plain error response rather than reconstructing every staged field.
- Existing Viewer read-only backend protection is retained.

## Data preservation
- This package retains the current `instance/database.db`, including existing users, tickets, transactions, and master part records.
- The database schema update only adds columns; it does not recreate tables or reset account passwords.
